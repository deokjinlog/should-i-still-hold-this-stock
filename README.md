# 이 주식, 여전히 들고 있어도 되나

<sub>같은 방식을 다른 도메인에 쓴 것 — [`can-this-be-redeveloped`](https://github.com/deokjinlog/can-this-be-redeveloped) (이 재개발 물건 사도 되나 · 판정선을 법령에서 얻는다)</sub>

살 때는 괜찮았습니다. **지금도 그런지**를 묻습니다 — 감사인의 경고도, 자본잠식 진행도,
사채 만기도 전부 산 뒤에 생기는 일이라서요.

전자공시로 **"이 회사 계속 들고 있어도 되나"** 에 근거를 대려던 기록이다.
점수를 내지 않는다. **무엇이 걸렸고, 그 검사가 검정을 통과했는지**만 낸다.

**▶ [실행 결과 화면](https://deokjinlog.github.io/should-i-still-hold-this-stock/)** — 어떻게
이 결론에 닿았는지, 무엇이 아홉 번 무너졌는지. · **▶ [측정 기록](docs/records.md)** —
검정 규율·신호 30종 전체·막다른 길.

## 결론

출발점은 "지분 구조로 부실을 예고한다" 였고, **그건 안 됐다.**

| | 검정한 신호 | 두 시점 전부 채택 |
|---|---:|---:|
| 지분 구조 | 7종 | **0종** |
| 재무·조달·오너·공시행태 | 23종 | **11종** |

안 된다는 걸 **재무 대조군을 같은 잣대에 넣어서** 보였기 때문에, "우리 방법이
틀렸다" 가 아니라 **"구조에 그 신호가 없다"** 로 말할 수 있다.

핵심 다섯은 규모·업종 통제 7설정 × 기준시점 2개 = **14조합 전부**에서 유의하다.

```
                  T=2023   T=2024        해당      부실률
  당기순손실         ×7.94    ×11.12    912~1,027사   5.6~10.8%
  영업손실          ×6.75     ×7.19      763~949사   5.5~11.4%
  결손금            ×5.32     ×8.86      744~759사   7.0~11.7%
  이자보상배율<1     ×4.23     ×5.78      714~901사   5.4~10.6%
  영업현금흐름 음수    ×3.34     ×4.75      764~810사   6.0~ 9.1%
```

**그런데 "이 회사는 망한다" 로 읽으면 안 된다.** 다섯 개가 전부 걸려도 이후 2년
부실률은 5.5~10.2% 다 — **열에 아홉은 아무 일도 없었다.** 가격·성장성·수익성은 아예
보지 않으니 **고르는 도구가 아니라 지우는 도구**다.

라벨을 관리종목까지 넓히면 검정력이 올라가 **9종이 더 채택된다**(부채비율 200% 초과가
거기서 처음 판정을 받았다). 어느 쪽도 정답이 아니라서 둘 다 낸다 —
[대조표](docs/records.md#답안지를-두-벌로-관리종목까지-세면-무엇이-달라지나).

### 규모

```
상장사 8,974개사 · 지분 관계 54,569건 · 기준시점 2개 (2023·2024)
답안지  부실 529건 + 관리종목 430건
검정 풀 2,692~2,739사 · 그 안의 부실 38~64사 (관리종목까지 세면 116~139사)
```

답안지는 두 번 고쳤다. **하나은행(532조)·신한은행·LG전자**가 "영업정지" 로 들어가
있던 걸 뺐고(금융당국 제재지 회사가 망한 게 아니다), 관리종목 지정 사유가 제목에
없던 107건이 **전부 유가증권**이라 본문에서 채웠다. 앞은 배율을 실제보다 작게
만들고 있었고, 뒤는 한 시장이 통째로 라벨에서 빠지는 편향이었다.

## 어떻게 쓰나

**① 종목 하나를 놓고 — 다섯 층으로 좁힌다**

```bash
uv run python scripts/report_company.py --name 부산주공
```
```
4개 걸림 — 이 구간의 실측 부실률 3.11~4.25%
  누적 손실이 3년째 커지는 중 — 231건 5.6% 대 악화 아님 161건 1.9%
  2023 감사보고서 · 계속기업 경고 — 69건 13.0% 대 경고 없음 1,160건 3.7%
  최근 3년 불성실공시 1회 — 64건 9.4% 대 이력 없음 366건 2.7%
  최근 3년 누계벌점 2.5점 (0~4점 구간) — 202건 4.0%
```

**개수 → 방향 → 감사 → 공시 행태** 순으로 좁혀진다. 개수만 보면 순서가 틀린다 —
같은 4개 걸림 안에서도 누적 손실 방향이 5.6% 대 1.9% 로 가른다.

문장마다 근거·표본·"다만" 이 붙는다. 판정하지 않고 **어느 구간인지와 그 구간의 실측
부실률**만 낸다.

**② 관심 종목을 걸어두고 — 새로 뜬 것만**

```bash
uv run python scripts/watch.py --add 부산주공
uv run python scripts/watch.py
```

같은 경고를 매일 다시 띄우면 사람이 읽기를 멈추고, 그러면 진짜 새 경고가 묻힌다.
새로 뜬 것만 알린다.

**③ 질문 → 그래프 검색**

```bash
uv run python scripts/ask.py "태영건설이 흔들리면 어디가 위험해?"
```

**질문에 없는 것을 가져온다** — 답에 `건설공제조합` 이 나오는데 그 이름은 질문 어디에도
없다. 벡터 유사도로는 안 나오고 한 홉 건너야 나온다. 다만 **검색이 잘 가져오는 것과
그게 부실을 예고하는 것은 다른 문제**였고, 이 저장소의 결론이 그 차이다.

모델은 근거 토큰 안에서만 말할 수 있고 벗어나면 `HallucinationDetected` 로 중단된다.

## 구조

```
DART OpenAPI + 공정거래위원회 공시 + KRX KIND
   ├─ 층0  이중 출처 신뢰 그래프 — 정형 API(정답) × 본문 추출(예측)
   └─ 층1  구조 분석 — [G1]품질·[G2]경계 게이트가 계산 앞을 막는다
            렌즈 → 가중치 → 투영 두 벌 → 군집(Leiden+CPM) → 층위·중심성
            → 귀무 대조 + 민감도 스윕 → 3상태 판정 → 근거 블록
```

규율을 문서가 아니라 **구조로** 강제한다. `db/asof.py`(시점 조회) ·
`signal/labels.py`(부실 판정) · `screen/inputs.py`(검사 입력) 가 각각 한 곳이다.
손으로 흩어 쓰면 언젠가 어긋나고, 실제로 어긋난 적이 있다.

Python 3.13+ / uv · igraph 1.0(Leiden+CPM) · networkx 3.6(차수보존 셔플) ·
SQLAlchemy 2.x · pytest **520**

Leiden 을 쓰는 이유는 Louvain 이 연결조차 안 된 군집을 만들 수 있어서고
(Traag et al., *Sci Rep* 9:5233, 2019), CPM 을 병행하는 이유는 모듈러리티가 일정 크기
미만 모듈을 원리적으로 못 봐서다(Fortunato & Barthélemy, *PNAS* 104(1), 2007).
실측 CPM 67 vs 모듈러리티 40 — **27개를 놓친다.**

> 패키지명은 `dartweave`. 초기 이름이며 import 경로 전체를 바꿀 이득이 없어 뒀다.

## 실행

```bash
uv sync --group dev
cp .env.example .env          # DART_API_KEY
uv run pytest -q              # 520 passed

uv run python scripts/report_company.py --name 종목명      # 다섯 층 리포트
uv run python scripts/watch.py --add 종목명 && uv run python scripts/watch.py
uv run python scripts/ask.py "질문"                       # 그래프 검색

uv run python scripts/test_financial_signals.py           # 신호 검정 (--include-warning)
uv run python scripts/compare_label_sets.py               # 답안지 두 벌 대조
uv run python scripts/sweep_window.py                     # 관측 창 민감도
uv run python scripts/adjust_multiplicity.py              # 다중검정 보정
```

`data/`는 gitignore 다. 수집 스크립트는 전부 재개 가능하다 —
`collect_timeseries`(지분) · `collect_financials`(주요계정) · `collect_cashflow`(현금흐름)
· `collect_industry`(업종) · `collect_events`(주요사항보고) · `collect_delisting`(상장폐지)
· `collect_audit_opinions`(감사의견) · `collect_kind_admin_history`(관리종목 이력)
· `collect_kind_bad_disclosure`·`collect_kind_penalty`(불성실공시·벌점).

> **남의 서버다.** `--min-interval` 을 줄이지 마라 — 0.15초로 8,878건을 때렸다가
> opendart 가 호스트째 막혔고, 풀리는 데 며칠 걸렸다. KIND 쪽은 페이지 끝을 넘기면
> 빈 응답이 아니라 **마지막 장을 되풀이해서** 준다(가드 있음).

> 이어받기는 **그 호출이 새로 주는 것** 기준으로 판단해야 한다. 한 번 호출에 당기·전기·
> 전전기가 오므로 `bsns_year=2021` 의 마진은 2019년이다. 당기로 판단하면 2023년 호출이
> 채워둔 값 때문에 통째로 건너뛴다 — 실제로 그렇게 한 해가 통으로 빠진 적이 있다.

## 한계

- **정밀도가 낮다** — 다섯 개가 전부 걸려도 열에 아홉은 2년 안에 무사했다.
  "이 회사는 위험하다" 를 말할 수 없고 "이 검사에 걸렸다" 까지가 한계다.
- **인과를 못 말한다** — "구조상 병목 위치에 있다" 까지가 데이터가 지지하는 범위다.
- **라벨이 얇다** — 검정 풀 안 부실이 T=2023 38사 · T=2024 64사다. 감사 경고가
  T=2024 에서 ×16.33 으로 가장 강한데도 좁은 답안지에서 판정 1/2 로 남는 이유가
  전부 여기고, 이건 데이터로 못 푼다 — 시간이 지나야 한다.
- **업종 통제가 시점 분리가 안 된다** — 현재 업종 코드를 과거 시점에 적용한다.
- **본문을 안 읽는다** — 정형 공시만 본다. 특수관계인 거래의 실제 금액은 본문에 있고,
  그걸 뽑으려면 재현율·정밀도부터 재야 한다.
